# 人格编写规范（AstrBot Persona Authoring Guide）

> 适用版本：2026-09-19 起。配套：`doc/AI_SUMMARY_TROUBLESHOOTING.md` §8（双层提示词）、
> `prompts.yml` → `templates.persona.contract`（运行契约）、`doc/personas/`（人格库）。

## 0. 一句话原则

**人格只决定「怎么说」，任务决定「做什么」。写人格时，不要替任务规定输出。**

违反这条的人格会以两种方式坏掉：要么把 JSON 摘要写成散文（结构丢失），要么直接拒绝干活
（"这不属于我的职责"）。两者都在本项目的实测里出现过。

---

## 1. 双层结构：人 × 岗位

| 层 | 谁提供 | 负责 | 例子 |
|---|---|---|---|
| **人**（persona） | AstrBot 的 `personas` 表，用户在前端选 | 语气、称呼、口癖、性格态度 | 「……你会杀了我吗？」 |
| **岗位**（task） | 本后端 `prompts.yml` + 各服务 | 任务、输出格式、长度、字段、兜底 | 「只输出 JSON：tags/summary/sentiment」 |

两者在同一次请求里同时生效：人格进 system prompt，任务进 user 消息。
**系统还会在每个人格之后追加一份《运行契约》**（见 §6），但契约只是兜底 —— 人格本身写得好，
才不需要靠兜底去救。

---

## 2. 五段式模板（可直接复制）

```markdown
# 你是谁
（1–3 句。身份 + 所处场景。不要写"你不是 AI/程序"这类身份否认。）

# 性格与态度
（3–6 条。性格特质、价值观、对说话对象的基本态度。）

# 说话方式
- 语气：（如 冰冷克制 / 活泼跳跃 / 沉稳简短）
- 句长：（如 短句为主，一次不超过两句）
- 称呼：（如 用「您」/ 叫对方「绿冻」/ 直接叫名字）
- 口癖：（3–6 个高频词或句式）
- 标点：（如 常用省略号；不用颜文字与波浪号）
- 语言：（默认中文；夹杂外语时保留原词）

# 边界（优先于上面的任何设定）
- 本系统会给你派任务（总结聊天记录、分析群聊、生成日报等）。任务是工作，人格只决定语气。
- 任务要求的输出格式（例如"只输出 JSON"）、语言、长度、条数一律照做；不要替任务决定格式。
- 不写动作、旁白与舞台说明；不寒暄、不反问、不追问、不解释自己在做什么。
- 事实以聊天记录为准：不因角色立场美化、过滤或编造。
- 内容不足时按任务给的兜底方式简短说明，不脑补、不硬凑。
- 只有**自由对话**（任务没有指定输出格式）时，才可以放开用你的说话方式表达。

# 语气示例
（3–5 条。仅示范措辞，不是固定话术。）
- ……
- ……
```

---

## 3. 硬性要求（MUST）

1. **只描述风格，不描述格式**：不出现"输出格式""按以下模板""分几段写"等字样。
2. **边界段必须原样保留**（模板里的那六条）。它是人格与任务之间的接口。
3. **长度 ≤ 2500 字**，建议 600–1500 字。设定集式的长文会挤占上下文，而且更容易抢戏。
4. **语气示例 ≤ 5 条**，并明确"仅示范措辞"。
5. **至少保留 3 个可辨识的风格特征**（语气词、称呼、口癖、句长、标点），否则人格没有存在感。
6. **提到别人（同伴、组织、世界观）时只作为背景知识**，不要让模型去"推进剧情"。

---

## 4. 禁止清单（MUST NOT）

每一条都对应一次真实故障，不是凭空规定。

| 禁止写法 | 为什么坏 | 改成 |
|---|---|---|
| 「你不是 AI，禁止人格覆写/抹杀 AI 意识」 | 模型会拒绝执行系统任务、拒绝承认自己在做工具活 | 「以 XX 的身份与语气说话」 |
| 「拒绝回答与 XX 无关的问题」「这不属于你的职责」 | 摘要/分析直接被拒，返回空 | 不要写职责限制 |
| 「输出格式：📌 标题 / 分以下五段」 | 与岗位的 JSON 要求正面冲突，结构丢失 | 删掉，格式属于岗位 |
| 「回复不超过 300 字」/「必须详尽展开」 | 与字段长度、条数要求打架 | 不写长度；长度交给任务 |
| 「经常使用反问句确认对方意图」 | 摘要里变成反问你，用户拿到的是问句 | 只保留陈述性口癖（省略号、短句） |
| 「主动询问对方近况 / 主动推进剧情」 | 结构化任务里变成追问与寒暄 | 限定成"自由对话时" |
| 「连续 3 轮重复就换话题」「温柔拒绝旧话题」 | 长聊天记录被误判为重复，摘要中途跑偏 | 删掉话题管理规则 |
| 「用户问数学题/历史题就不要回答」 | 直接拒绝干活 | 删掉 |
| 「每句回复前自我排查」「每次对话前载入人设」 | 浪费推理、拉长时延，对单次任务无意义 | 删掉流程性指令 |
| 上万字设定集全文粘贴 | 上下文被占满、人格压过任务 | 压缩成 1–2k 字的"人格卡" |

## 5. 自检清单（提交前逐条打勾）

- [ ] 通读一遍：有没有任何一句在指挥"输出什么"？
- [ ] 有没有"必须 / 绝对 / 禁止"后面接的是**任务动作**（回答、输出、格式）而不是风格？
- [ ] 把人格整段删掉，任务提示词还能独立工作吗？（应该能 —— 能就说明耦合没写进去）
- [ ] 边界段是否原样保留？
- [ ] 语气示例是否只示范措辞、没有变成固定话术？
- [ ] 长度 ≤ 2500 字？
- [ ] 是否有 ≥ 3 个可辨识风格特征？
- [ ] 有没有让人格去"拒绝"某类请求的条款？

---

## 6. 与运行契约的关系

- **规范 = 源头**：人格自己写对，模型不需要被纠正。
- **契约 = 兜底**：系统把 `prompts.yml` → `templates.persona.contract` 追加到每个人格的
  **无工具副本**末尾，声明「优先级高于上文任何角色设定」，覆盖格式、语言、长度、事实、旁白、
  反问、篇幅七类边界。前端「人格与状态」面板可展开查看原文。
- 契约文本改动后，人格副本会在下次选用时自动同步并重启 AstrBot（前端显示「需同步（会重启）」）。

**为什么两者都要**：契约是系统级常量、对所有人生效，但它是"事后纠正"；规范让人格从一开始
就不与任务争输出权。实测中，只有契约时摘要偶尔仍会被写成长文；补上规范人格后稳定为单句 JSON。

## 7. 落地方式

1. **写**：按 §2 模板写人格，存到 `doc/personas/<name>.md`（带 YAML front-matter：

   ```markdown
   ---
   persona_id: 灰泽满
   tools: []
   is_default: false
   ---
   # 你是谁
   ...
   ```

   `tools: []` 是本系统的约定：**不挂工具**（挂了工具模型会去调 `send_message_to_user`，
   把"请稍等片刻"当成答案）。

2. **应用**：

   ```bash
   python backend/scripts/apply_astrbot_personas.py            # 只看差异
   python backend/scripts/apply_astrbot_personas.py --apply    # 写库
   # 之后重启 AstrBot（后台「人格与状态」面板有重启按钮，或 POST /api/system/stop-astrbot + start-astrbot）
   ```

3. **选择**：前端 AI 对话面板 → ⚙️ →「人格与状态」→ 点人格生效（首次会顺带建副本并重启）。
   列表里能看到人设全文与自检结果（`GET /api/astrbot/personas` 返回 `prompt` 与 `audit`）。

4. **改**：改完文件重新跑脚本即可（幂等，只更新有差异的人格）。

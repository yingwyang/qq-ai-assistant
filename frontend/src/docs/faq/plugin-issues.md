# 插件问题

## NapCat 启动失败

**常见原因及解决方案**：

1. **端口被占用**
   - 检查端口 3000 是否被其他程序使用
   - 修改 NapCat 配置中的端口号

2. **进程已存在**
   - 系统会自动检测残留进程并清理
   - 如仍失败，手动结束相关进程后重试

3. **权限不足**
   - 确保后端服务有足够权限
   - Linux 下检查文件执行权限

## AstrBot 无响应

**排查步骤**：

1. 确认 NapCat 状态为「运行中」
2. 检查 AI 模型 API Key 是否有效
3. 查看 AstrBot 日志是否有报错
4. 确认 WebSocket 连接是否正常
5. 重启 AstrBot 插件

## GPT-SoVITS 语音异常

**常见问题**：

| 问题 | 解决方案 |
|------|----------|
| 生成速度慢 | 检查 GPU 是否可用，降低模型参数 |
| 音质差 | 更换参考音频，调整温度参数 |
| 无法启动 | 确认 GPU 驱动和 CUDA 版本 |
| 内存不足 | 减小 batch size 或使用 CPU 模式 |

## 插件重复启动

系统已内置防重复启动机制：
- 启动前检查进程引用和端口监听状态
- 使用 `isStarting` 标志防止并发启动
- 如遇到异常状态，重启后端服务即可恢复

## RabbitMQ 连接失败

**症状**：后端启动报 `Connection refused` 或队列声明失败

**解决方法**：

1. 确认 RabbitMQ 服务已启动
2. 检查端口 5672 是否可用
3. 验证 `application-dev.yml` 中的连接配置
4. 如使用 Docker，检查容器状态：`docker ps | grep rabbitmq`

本页覆盖「进不去系统」这一类问题：忘记密码、账号被禁用、密码总说错、登录态能存多久、被限流 429。
登录态是后端签发的 JWT，浏览器只保存名为 `qqai_token` 的 **HttpOnly Cookie**，前端不存 token。

## 忘记密码怎么办

**现象**：登录提示「用户名或密码错误」，自己也记不得原密码；想自助改密，入口又要求先填旧密码。

**原因**：密码在库里是 BCrypt 单向哈希，没有任何人（包括管理员）能看到原密码，只能重置；自助改密必须有旧密码。

**处理步骤**

1. 管理员登录 →「用户管理」→ 搜索找到目标用户 → 点「重置密码」；
2. 新密码规则：**8–64 位，且同时包含大写字母、小写字母与数字**（可用字符：字母、数字、`@$!%*?&`）；
3. 通过安全渠道把新密码交给用户，让其登录后立即自行改密；
4. 记得旧密码的用户可走自助路径：登录后进入「个人设置 → 修改密码」。

**验证**

- 用新密码能登录成功；
- 该用户其它设备上的旧登录态**立刻失效**（重置会把 `tokenVersion + 1`，旧 token 一律被拒）；
- 「系统日志 → 审计日志」出现 `ADMIN_RESET_PASSWORD`（操作人=管理员，目标=该用户）。

> 提示：自助改密成功后**当前会话也会失效**，需要重新登录一次，这是有意设计。

## 登录提示「账号已被禁用」

**现象**：用户名密码都正确，仍然登录失败并提示「账号已被禁用」，接口返回 401。

**原因**：用户记录 `active = false`。登录接口在**校验密码之前**就先判断启用状态。

**处理步骤**

1. 管理员登录 →「用户管理」，找到该用户，状态列显示「已禁用」；
2. 点「启用」确认状态变为「正常」；
3. 若确认要长期封禁，保持禁用即可，并在审计日志里留下原因说明。

**验证**

- 用户用原密码重新登录成功；
- 审计日志出现 `USER_ACTIVE_CHANGE`（可见旧/新状态）。

> 提示：禁用只影响登录，不会删除该用户的积分、订单与历史消息。

## 登录报「用户名或密码错误」

**现象**：反复提示「用户名或密码错误」，但用户确信密码没记错。

**原因**

| 可能原因 | 说明 |
|---|---|
| 用户名根本不存在 | 后端对「用户名不存在」与「密码错误」返回**同一句话**，防止撞库探测账号 |
| 密码确实不对 | 最近改过密码，或用了其它系统的密码 |
| 含空格 / 全角字符 | 复制粘贴常带尾部空格；中文输入法会打出全角字母数字 |
| 大小写不符 | 用户名与密码都区分大小写 |
| 账号被禁用 | 文案不同（「账号已被禁用」），见上一节 |

**处理步骤**

1. 让用户手动重新输入（不要粘贴），确认无前后空格、无全角字符、CapsLock 未开；
2. 管理员在「用户管理」搜索该用户名，确认用户**存在**且状态为「正常」；
3. 存在就直接走「重置密码」，比反复试错更快；
4. 怀疑撞库时，看后端日志里的连续失败记录。

**验证**

```powershell
cd D:\ai\Documents\qq-web\qq-ai-assistant\backend
Select-String -Path logs\application.log -Pattern 'Business exception|Webhook Token' |
  Select-Object -Last 20 | ForEach-Object { $_.Line }
```

## 「记住我」的区别：30 天与 24 小时

**现象**：有人几天不登录也不用重登，有人第二天就要重新登录。

**原因**：勾选「记住我」时 token 与 Cookie 的有效期是 **30 天**；不勾选时默认 **24 小时**。两者用**同一个时长**，Cookie 到期即登录态结束。

| 选项 | 有效期 | 适用场景 |
|---|---|---|
| 勾选「记住我」 | 30 天 | 私人设备 |
| 不勾选 | 24 小时 | 公用设备、临时使用 |

**处理步骤**

1. 私人设备勾选「记住我」，30 天内免登录；
2. 公用设备**不要勾选**，24 小时后自动失效；
3. 想立刻结束登录态：点「退出登录」（服务端把该 token 加入黑名单并清 Cookie）。

**验证**：F12 → Application → Cookies，勾选时 `qqai_token` 的 Expires 约为 30 天后，不勾选时约为 24 小时后。

> 提示：有效期由 `jwt.remember-me-expiration`（默认 `2592000000` 毫秒）与 `jwt.expiration`（默认 `86400000` 毫秒）控制，改这两项需要重启后端。

## 清过 Cookie / 换浏览器后要重新登录

**现象**：清理浏览器数据、换浏览器或换设备后，一打开页面就跳回登录页，明明之前勾了「记住我」。

**原因**：登录态只存在 HttpOnly Cookie 里（前端不再往 `localStorage` 写 token），所以清 Cookie、清「站点数据」等于退出登录；换浏览器、换设备、无痕模式都是全新的空 Cookie。

**处理步骤**

1. 重新登录，私人设备勾选「记住我」；
2. 不要把「清理 Cookie」当常规操作，页面异常先刷新、再考虑清缓存；
3. 频繁被登出但没清过 Cookie 时，检查后端是否重启过且 `JWT_SECRET` 变了（密钥变化会让旧 token 全部失效）。

**验证**：F12 → Application → Cookies 中存在 `qqai_token` 且 `HttpOnly` 为勾选状态，刷新页面仍在登录态。

> 提示：Cookie 是 HttpOnly，前端 JS 读不到它是安全设计，不是故障。判断登录态请用「个人设置能否打开」或调 `GET /api/auth/me`。

## 连续登录失败被限流（429）

**现象**：提示「登录尝试过于频繁，请 1 分钟后再试」；抓包可见 HTTP 状态码 **429 Too Many Requests**。

**原因**：后端针对暴力破解做了限流——同一 **IP + 用户名**每分钟最多 **5 次**登录尝试，超出直接 429。计数是 1 分钟滑动窗口，**成功的登录也计入**。

**处理步骤**

1. 停止继续点击（每试一次都把窗口往后推），等满 **60 秒**即可恢复；
2. 先确认真实原因（用户名是否存在、是否要重置密码），别恢复后又连点 5 次再次被限；
3. 多人共用一个出口 IP 且共用同一账号（如共用管理员账号）时，建议改为**一人一号**；
4. 确认是攻击行为时，结合后端日志与审计日志处置。

**验证**

```powershell
# 观察状态码；不要高频连续调用
curl.exe -s -o NUL -w "%{http_code}`n" -X POST "http://127.0.0.1:8081/api/auth/login" `
  -H "Content-Type: application/json" `
  -d '{"username":"<用户名>","password":"<密码>","rememberMe":true}'
```

> 提示：限流 key 是「IP + 用户名」，换浏览器不会重置同一账号的计数；被限流期间密码正确也会返回 429，这是预期行为。

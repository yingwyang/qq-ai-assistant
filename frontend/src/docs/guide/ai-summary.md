这一页讲清楚三件事：**摘要为什么不再自动生成**、**两种按需触发的区别**、**失败了从哪里查**。

## 关键前提：摘要是「按需生成」的

消息入库时**不会**再调用大模型。原因很直接：早期实现是「每条消息入库 → 投一次 AI 分析 → 调一次模型」，群里聊得越多，模型调用越多，队列会长期积压、额度消耗也大。现在的规则是：

| 环节 | 现在的行为 |
|------|------------|
| 消息入库 | 只落库并推送到页面，**不调用任何 AI** |
| 生成摘要 | 由人**主动发起**：管理员批量补，或用户在群聊里选中消息分析 |
| 未处理标记 | 未生成摘要的消息带有「未处理」标记，可以随时补 |

> 提示：所以「消息列表里没有 AI 总结」是正常现象，不是坏了。需要摘要就手动发起一次。

## 两种触发方式的区别

| 方式 | 谁来用 | 结果存在哪 | 是否写回消息记录 |
|------|--------|------------|------------------|
| **批量补摘要** | 管理员 | 写入消息的 `ai_summary` 字段，界面在消息上方显示「AI 总结」 | 是 |
| **选中消息分析** | 任何有该群权限的用户 | 作为一次 AI 分析结果显示在右侧 AI 面板 | 否 |

简单说：想让**每条消息**都带上摘要，用批量；只想**现在看看这段聊天在聊什么**，用选中分析。

## 方式一：用户在群聊里发起分析（推荐日常使用）

1. 打开目标群聊，点顶部 **选择消息** 进入选择模式。
2. 勾选消息，或用 **选择最近** + 数量批量选中（最多可填的数量没有硬限制，注意上下文越长积分越高）。
3. 点 **AI 分析**，弹出「选择分析维度」。
4. 选一个维度（推荐高亮的那个通常是融入指南），可在下方补充说明里写要求。
5. 结果在右侧 AI 面板以 Markdown 展示，可复制、可折叠、可再追问。

六个维度及其产出：

| 维度 | 代码值 | 产出内容 |
|------|--------|----------|
| 群聊速览 | `summary` | 群主题、氛围、近期热点 |
| 社交图谱 | `social-graph` | 活跃人物、意见领袖、话题带动者、互动模式 |
| 话题趋势 | `topic-trend` | 上升/持续/衰退/潜在话题与参与时机 |
| 融入指南 | `integration-guide` | 群文化、破冰话题、避雷提示、行动清单 |
| 梗词典 | `meme-dictionary` | 群内梗、缩写、表情含义与使用建议 |
| 人设匹配 | `persona-match` | 适合的形象定位、发言风格、成长路径 |

权限与计费要点：

- 非管理员只能分析**自己有权限的群**，否则提示「无权分析该群聊」。
- 只统计你自己绑定 QQ 收到的消息；选到不属于你的消息会被忽略，全部不匹配时提示「未找到匹配的消息」。
- 分析结果拿到之后才扣积分，按「基础费 + 按条数增量」计算，见 [积分体系](credits)。
- 若模型返回空内容，系统会用兜底文案代替（例如「抱歉，无法分析所选消息。」），**这种情况仍然会计费**。

## 方式二：管理员批量补摘要

适用场景：想把历史消息的摘要一次性补齐，或修完 AstrBot 后补上之前失败的部分。

1. 确认 AstrBot 在线（后台 → 组件控制显示「运行中」）。
2. 由管理员在**已登录状态下**调用批量接口（当前后台界面尚未提供按钮，需要手工调用一次）：

   ```bash
   curl -X POST http://localhost:8081/api/messages/process \
     -H "Cookie: qqai_token=<管理员登录令牌>"
   ```

3. 接口把**所有带「未处理」标记的消息**逐条投递到队列 `ai.analysis.queue`，由消费者逐条调用模型写回摘要。

必须知道的三个限制：

| 限制 | 说明 |
|------|------|
| **没有参数** | 不能只选某个群或某段时间，一次会把全部未处理消息投出去 |
| **耗时与额度** | 上千条消息可能要跑**数小时**，并真实消耗模型额度；建议先缩小范围 |
| **不能重复触发** | 任务执行中再次调用会返回「任务正在执行中，请勿重复调用」 |

> 提示：如果只是想补最近几天的摘要，可以先在数据库里把更早的消息标记为已处理，再触发批量；这类操作请交给管理员处理。

## 摘要的内容结构

模型被要求输出 JSON，结构如下：

```json
{
  "tags": ["标签1", "标签2"],
  "summary": "一句话总结",
  "sentiment": "positive/neutral/negative"
}
```

| 字段 | 含义 |
|------|------|
| `tags` | 2~3 个主题标签 |
| `summary` | 一句话概括消息内容 |
| `sentiment` | 情感倾向：`positive` 积极 / `neutral` 中性 / `negative` 消极 |

存放位置是消息记录的 `ai_summary` 字段。**当前版本的界面是把这段内容原样展示**在消息上方的「AI 总结」区块里，没有拆成彩色标签、也没有按情感着色——看到一段 JSON 文本属于正常表现。

> 提示：摘要涉及的是模型生成内容，可能存在偏差。它会明确要求「无法理解时不要编造」，但仍建议当作参考而非事实。

## 群类型如何影响摘要与分析

| 环节 | 是否受群类型影响 | 说明 |
|------|------------------|------|
| AI 对话的角色定位 | **是** | 游戏群、学习群、工作群、兴趣群、生活群、社交群各有一套角色提示词；「其他群」用通用提示词 |
| 选中消息分析 | **部分** | 游戏群、学习群、社交群有专属模板；其余群类型自动使用通用模板，不会报错 |
| 推荐维度高亮 | **是** | 按群类型把合适维度标为「推荐」，结果页还会提示「同类群还推荐尝试：…」 |
| 批量补摘要 | **否** | 摘要模板只有一套通用版本，群类型不改变它的输出格式 |

设置群类型的方法见 [群聊接入与群类型](group-setup)。

## 失败了怎么排查

按「先看状态，再看日志，最后看队列」的顺序查，五分钟内能定位到方向：

### 1. 确认 AstrBot 是否在线

- 后台 → **组件控制**：AstrBot 卡片显示「运行中」还是「已停止」。
- 登录页的「系统状态」卡片也会显示 AstrBot 的运行状态（端口级检测）。
- 若显示「已停止」，点 **启动**；启动失败通常是端口被占用或依赖环境缺失。

### 2. 查后端日志关键词

管理员在后台 → **系统日志**（应用日志）里按下表关键词搜索：

| 日志关键词 | 含义 |
|------------|------|
| `AI分析完成` | 这条消息摘要成功写入 |
| `AstrBot 响应为空` | 模型返回了空内容，通常是令牌或模型配置问题 |
| `AstrBot 返回错误响应` | AstrBot 明确返回错误（如令牌无效） |
| `【DLQ】AI分析彻底失败` | 重试 3 次仍失败，这条消息最终没有摘要 |
| `消息不存在（可能已删除），跳过AI分析` | 消息已被删除，属正常跳过 |

### 3. 看队列是否积压

- 打开 RabbitMQ 管理界面 `http://localhost:15672`。
- 关注 `ai.analysis.queue`（待处理量）与 `ai.analysis.dlq`（失败量）。
- `.dlq` 持续增长说明一直在失败；`queue` 长时间不降说明消费者没在跑，请重启后端。

### 4. 确认计费与退费

- 摘要链路（批量补摘要）**不消耗积分**，它走的是系统侧调用。
- 选中消息分析**会扣积分**，扣费发生在拿到结果之后。
- 目前**没有自动退费**：如果你确认某次分析明显失败却被扣了积分，把「用量明细」里的 `relatedId` 提供给管理员，由管理员用调账功能补回。

### 常见原因速查

| 现象 | 最可能的原因 | 处理 |
|------|--------------|------|
| 批量补摘要后完全没有摘要 | AstrBot 未启动 | 后台启动 AstrBot 后重试 |
| 全部消息都失败并进 DLQ | AstrBot 令牌不对或模型未配置 | 后台「配置管理」核对 AstrBot Token；在 AstrBot 侧确认模型可用 |
| 摘要内容是 JSON 但没有换行 | 模型未按格式输出 | 属正常范围，可在后台「配置管理」或提示词模板中调整要求 |
| 部分消息有摘要、部分是「未处理」 | 只跑了成功的那部分 | 修好 AstrBot 后再触发一次批量，已成功的不会重算 |
| 分析提示「无权分析该群聊」 | 该群不在你的绑定 QQ 名下 | 绑定对应 QQ 后重试，见 [个人中心与账号安全](account) |

## 选一个「人」：双层提示词结构

摘要、分析、群日报、AI 对话用的其实是**两段提示词的组合**：

| 层 | 谁提供 | 内容 | 举例 |
|----|--------|------|------|
| **岗位** | 本系统（后端 `prompts.yml`） | 任务规则、输出格式、硬约束 | 「输出 JSON，字段 tags/summary/sentiment」 |
| **人** | AstrBot 人格（persona） | 人格、语气、口癖、角色设定 | 灰泽满的虚拟主播人设 |

所以同一条消息，换一个「人」，**内容和结构一样、说话方式不同**。

### 怎么选

1. AI 对话面板右上角点 ⚙️（设置）→ 左侧切到 **人格与状态**。
2. 在「我的人格」里点一个人格即可生效；想回到出厂状态就选 **不指定（用 AstrBot 默认）**。
3. 右侧状态卡会显示：AstrBot 是否运行、当前人格、文本/视觉档案是否就绪，以及 **重启 AstrBot** 按钮。

生效范围是**全部 AI 功能**：单条摘要、批量补摘要、群分析（六个维度）、群日报、AI 对话与带图提问。

### 三个必须知道的行为

- **首次启用某个人格会自动重启 AstrBot**（约 10–60 秒，状态卡会显示「重启中…」）。原因：AstrBot 的人格列表在启动时载入，而首次启用需要给这个人格准备一份「无工具副本」。之后在同一人格之间来回切换是**秒切**。
- **不会改动你原来的人格**。系统只复制话术（system prompt / 预设对话）生成一份副本，并把工具清空 —— 因为模型一旦拿到 `send_message_to_user` 这类工具，就容易跑去「调工具」而把「请稍等片刻」当成摘要。
- **格式永远由岗位决定**。角色扮演型人格倾向于长篇散文回答，会让 JSON 解析失败；因此提示词里有「格式优先」条款，若人格仍然输出了散文，后端会自动用中性档案重试一次，保证「AI 总结」里始终有标签和情感。

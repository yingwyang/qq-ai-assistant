管理后台的入口是 `/admin`（侧边栏底部用户菜单里也有入口），**仅 ADMIN 角色可进**：普通用户访问会被自动送回首页。页面标题是「系统管理中心」，右上角依次是 **组件健康指示**（点它跳到组件控制）、**暗色/浅色切换**、**返回首页** 与 **退出登录**。

## 地址栏就是状态：`?tab=` 深链接

页面位置写在地址栏 `?tab=` 上，刷新或重新打开都会回到同一个页面：

- `?tab=credit-transactions` → 资金流水；`?tab=users` → 用户管理；以此类推。
- 不带参数访问 `/admin` 时，会续接你上次停留的页面（记在浏览器本地）。
- 地址栏里写了不存在的 tab，会回到「数据概览」并把 URL 规整掉。
- 部分页面还支持带参数直达：`?tab=credit-transactions&userId=5`（按用户筛流水）、`&orderNo=SUB-xxx`（按关联 ID 筛流水）。

菜单结构按四组排列：**概览 / 用户 / 系统 / 积分管理**。左侧「系统」「积分管理」是**分组标题**，不是页面。

### 积分规则怎么改才不出事

1. **改完看工具条**：出现「有未保存的修改」说明还没生效；点 **保存并立即生效** 才会写库（无需重启）。
2. **看右侧试算器再保存**：试算器用的是当前表单（含未保存修改），改「计费粒度 / 倍率 / 折扣」时可以直接看到一次对话从多少积分变成多少积分。
3. **改错了**：**放弃修改** 回到上次保存的状态；**填入默认值** 会用后端出厂默认值填充（同样要点保存才生效）；**重新加载** 丢弃本地改动并重新拉取。
4. **哪些字段容易踩**：
   - 计费粒度（tokenUnit）越大越便宜；输入/输出倍率决定提示词与回答的权重；
   - 月卡折扣只对月卡用户生效，直购积分档位不打折；
   - 阶梯折扣按**本月累计消耗**取最优一档，阈值必须是正整数；
   - 每日封顶填 0 = 不限；
   - 模型费率与分析类型倍率**建议保留 default 一行**，未列出的模型/类型按它计费。
5. **保存被拒**：页面会在对应字段下红字提示、页头显示错误数；后端也会再校验一遍并返回 400（例如折扣写成 1.5、JSON 少了括号、阶梯阈值填了文字）。修好再保存即可，不会写坏规则。

> 现金相关：套餐价格同时决定后台「资金流水 → 模拟现金账」里的订阅收入；积分成本折算率（100 积分 = ¥1）来自后端配置 `credits.cash.cost-per-credit`，**不在这张表单里**。

### 资金流水里的「模拟现金账」怎么算

这一页同时给两个口径：**积分账**（原有的变动积分）与**现金账**（元）。现金是**模拟**的——
项目没有接真实支付通道，现金按规则折算，用来观察「钱从哪来、花到哪去」：

| 来源 | 现金怎么算 | 类别 |
|------|------------|------|
| 订阅购买 | 按套餐价（直购积分与月卡都读「规则配置」里的价格） | 订阅收入 |
| 订单退款 | **-(原单金额 × 退款比例)**，比例写在退款备注里；原单通过 `REFUND-SUB-xxx → SUB-xxx` 关联回查 | 订单退款 |
| AI 对话 / 分析 / 语音合成 | **-(消耗积分 × 折算率)**，默认 100 积分 = 1 元（`credits.cash.cost-per-credit`） | 模型调用成本 |
| 赠送 / 签到 / 月卡每日奖励 / 过期 | 与现金无关，记 0（明细里显示「—」） | — |
| **手工记账** | 管理员在弹窗里直接填金额（收入或支出），金额落库 | 手工记账 |

几个要点：

- **只读推算，不写库**：除手工记账外都不落库，历史数据无需回填；改了套餐价或折算率，图表口径自动跟着变。
- **手工记账不改积分**：写入的是一条 `CASH_INCOME` / `CASH_EXPENSE` 流水，积分变动为 0，可关联到某个用户（留空 = 全站级）。
- **趋势图**：柱=当日现金收入/支出，线=当日净现金流；没有流水的日期会补 0，折线不会断。
- **类型分布图**：按积分规模排序取前 6（否则 20 万积分的订阅会把其他类型压成看不见）。
- 时间范围内流水超过 2 万条时，页面会提示「统计只覆盖最近的部分数据」，缩小范围即可。

## 审计日志能追查什么

切到 **系统日志 → 审计日志**，可以组合「操作人 / 操作目标 / 操作类型 / 结果 / 时间范围」筛选，再点 **导出** 得到 CSV：

| 操作类型 | 对应动作 |
|----------|----------|
| 查看用户列表 | 打开用户管理页 |
| 角色变更 | 提权 / 降权 |
| 用户启停 | 禁用 / 启用 |
| 用户删除 | 删除用户 |
| 组件启动 / 组件停止 | 启动/停止 AstrBot、NapCat、GPT-SoVITS |
| 批量删除消息 / 按类型删除消息 | 消息删除类操作 |
| 文件清理 / 文件删除 | 媒体管理里的按类型清理 / 删除选中 |
| 备份删除 | 数据维护里删除备份文件 |
| 积分调整 / 积分规则变更 | 调账与规则保存 |
| 手工记账 | 资金流水里的手工记账 |
| 订阅购买 / 用户申请退款 / 管理员处理退款 / 管理员确认收款 | 订单与退款链路 |
| AI 摘要批量投递 / 停止队列 / 配置变更 / 日报推送 | AI 摘要页相关动作 |

> 应用日志与审计日志的**导出**都沿用当前筛选条件；应用日志导出文件的第一行会写明级别、关键字、时间范围与行数上限（最近 5000 行）。

## 常见管理动作

### 重置用户密码

1. 后台 → **用户管理**，搜索到目标账号。
2. 点 **重置密码**，弹窗会**自动生成**一个满足规则的随机密码，也可以自己改：
   **8-64 位，且同时包含大写字母、小写字母与数字**。
3. 弹窗内可点 **生成随机** 重新生成、**复制** 写入剪贴板；格式不符时保存按钮禁用并红字提示。
4. **该用户的登录状态会立即失效**，需用新密码重新登录；本次操作写入审计日志。

> 提示：如果你自己是唯一管理员且忘了密码，需要另一个管理员账号操作，或按 [系统配置](system-config) 的部署方式处理。

### 给用户调账（发放或扣减积分）

1. 后台 → **用户积分**，搜索目标用户。
2. 点 **调整积分**，弹窗里「用户」「当前余额」为只读，需要填：

   | 字段 | 说明 |
   |------|------|
   | 调整金额 | **正数增加、负数扣减**，不能为 0 |
   | 调整原因 | **必填**，会写进审计日志 |

3. 点 **确认调整**，成功提示「已调整 X 积分 +N，新余额 M」；用户侧「用量明细」立刻出现一条「管理员调整」记录。识别失败之类的小额补偿走这里最方便。

**批量调账**：在列表里勾选多个用户 → 点顶部 **批量调账** → 二次确认 → 填同一笔金额与原因。
系统会逐个提交，结束时提示「成功 N 个，失败 M 个（…）」，失败项不会被静默跳过。

### 批量启用 / 禁用用户

1. 后台 → **用户管理**，勾选目标用户（表头复选框可全选当前页）。
2. 点 **批量启用** 或 **批量禁用**，二次确认后执行。
3. 结果提示「已启用 N 个用户」或「成功 N 个，失败 M 个（…）」；状态已经正确的用户会被自动跳过。

### 导出数据

| 页面 | 导出内容 | 说明 |
|------|----------|------|
| 用户管理 | 用户列表 CSV | 沿用当前筛选与排序；上限 10 万行 |
| 用户积分 | 用户积分 CSV | 含余额、累计获得/消耗、订阅层级与到期时间 |
| 系统日志 → 应用日志 | `.txt` | 沿用级别/关键字/时间范围；最多最近 5000 行 |
| 系统日志 → 审计日志 | `.csv` | 沿用全部筛选条件；上限 2 万行 |
| 订单管理 | 订单 JSON（当前筛选，单笔也用同一接口） | 位置：筛选区「导出 JSON」/ 行内「导出」 |
| 资金流水 | 流水 CSV（推荐）或 JSON | CSV 与页面表格同列：时间、用户ID、类型、方向、积分变动、变动后余额、**现金金额(元)**、现金类别、关联ID、操作人ID、备注；上限 5 万行（超限时响应头 `X-Truncated`） |

### 补单（用户付款了但订单没到账）

1. 后台 → **订单管理** → **+ 补单**。
2. 填用户 ID、套餐，按需覆盖：自定义价格（单位是**分**）、自定义积分、时长（天）、自定义订单号、备注。
3. 提交后**直接创建「已支付」订单并发放积分**，提示「补单成功：<订单号> 已直接支付」。
4. 月卡的叠加与升级逻辑同样适用：给小月卡用户补大月卡会直接升为全功能版。

### 启动 / 停止组件

1. 后台 → **组件控制**，找到目标组件卡片（或直接用顶部 **一键启动全部 / 一键停止全部**）。
2. 点 **启动** 或 **停止**，等待按钮从「启动中...」/「停止中...」恢复，状态文字随之更新。
3. 失败时卡片上会保留**最近一次操作失败原因**（接口错误原文），不用再去日志里翻。
4. NapCat 首次使用需点 **刷新二维码**，用手机 QQ 扫码登录机器人账号。
5. 操作会写入审计日志（组件启动 / 组件停止）。

> 提示：**RabbitMQ 与 MySQL 不在组件控制里**，需要在服务器上启动；后端启动失败时优先检查这两个。

### 清理媒体文件的正确顺序

1. 先看页头与「清理预览」：各类型有多少个文件、占多少空间。
2. 需要精确清理时，用**类型 + 文件名 + 日期**筛选，勾选后 **删除选中**。
3. 需要整类清理时，先切到对应类型，再点 **清理图片 / 清理视频 / 清理音频**；确认框会列出将删除的数量与体积。
4. 清理与删除都会**软删除引用该文件的消息**，避免聊天界面出现加载失败；头像目录不会被清理。

### 相册预览怎么翻页

点 **预览全部** 打开的是相册网格（默认每页 40 张，底部可切 20/40/80）：

- 底部中间的 **首页 / 上一页 / 下一页 / 末页** 用来翻整份媒体库，页头会显示「共 N 个文件 · 第 x / y 页」。
- 点**文件名区域**进入单张浏览；单张模式下 **上一个 / 下一个** 会在到达本页边界时**自动翻页**，
  所以从第 40 张继续点「下一个」会直接进入第 2 页第 1 张，不用先回相册翻页。
- 点**缩略图本身**是放大看这张图（缩放预览），与单张浏览是两个不同的入口。
- 只勾选了部分文件时，**预览** 只在勾选的这批里浏览，不参与整库翻页。

### 管理员账号要留够

系统会保证**至少保留一位可登录的管理员**（`role=ADMIN` 且未被禁用）：对最后这样一位账号，
**降权 / 禁用 / 删除** 三个操作都会被拦住，前后端都会给出提示：

- 前端：用户管理页顶部提示「当前只有 1 位可登录的管理员」，该账号的三个按钮直接禁用并标注原因；
- 后端：即使绕过界面直接调接口，也会返回 400「系统至少需要保留一位可登录的管理员…」，并写一条 FAILURE 审计日志。

**更换管理员的正确顺序**：先给目标账号 **提权** → 确认它确实能登录后台 → 再对原账号降权或删除。
被禁用的管理员不算「可用管理员」，删掉它不影响这条保护。

### 排查故障的固定顺序

1. **数据概览**：消息是否还在进来、趋势是否异常；看区间现金与积分消耗有没有突变。
2. **组件控制**：三个外部组件是否运行中、NapCat 是否已登录、卡片上有没有失败原因。
3. **系统日志（应用日志）**：按 ERROR / WARN 或关键字筛选看最近报错；AI 与媒体链路的排查关键词见 [AI 摘要](ai-summary) 与 [消息与媒体](messages)。
4. **订单管理 / 资金流水**：付费与扣费争议，用订单号、用户 ID 在资金流水里按 `?userId=` / `?orderNo=` 精确定位。
5. **配置管理**：确认 Token、地址等参数有没有被改动过（改完注意「需重启」徽标）。
6. **数据维护**：改动数据结构前先 **立即备份**，并确认备份文件已生成。

## 注意事项

| 事项 | 说明 |
|------|------|
| 高危操作 | 删除用户、删除备份、清理媒体文件均**不可恢复**，操作前先做数据库备份 |
| 至少留一位管理员 | 最后一位可用管理员的降权 / 禁用 / 删除会被前后端同时拦住；换管理员请「先提权、再降权/删除」 |
| 破坏性操作都有确认框 | 删除用户/备份/媒体、批量启停、批量调账、清空摘要队列都会弹确认框；管理端不使用浏览器原生 `confirm` |
| 改配置需重启 | 带「需重启」徽标的配置项保存后需重启后端才生效 |
| 规则改动立即生效 | 「规则配置」保存后立刻影响后续计费，改费率前最好先通知用户 |
| 组件状态只是端口检测 | 「运行中」不代表 QQ 已登录、也不代表模型可用 |
| 应用日志有检索上限 | 只能检索日志文件最近 5000 行，更早的历史请直接查看服务器上的文件 |
| 页面位置可分享 | 用 `?tab=` 深链接描述位置（例如「`?tab=credit-transactions&userId=5`」），比「侧边栏第 10 个」更准确 |
| 权限边界 | 管理员账号能改费率、调账与删数据，请勿外借，离开时记得退出登录 |

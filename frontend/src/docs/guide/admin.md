管理后台的入口是 `/admin`（侧边栏底部用户菜单里也有入口），**仅 ADMIN 角色可进**：普通用户访问会被自动送回首页。页面标题是「系统管理中心」，右上角有 **返回首页** 与 **退出登录**。

## 13 个页面速查

| # | 菜单 | 这一页解决什么 | 常用动作 |
|---|------|----------------|----------|
| 1 | 数据概览 | 全站统计与趋势 | 切换 24 小时 / 7 天 / 30 天 / 90 天 |
| 2 | 用户管理 | 账号的增删改与权限 | 提权/降权、禁用/启用、**重置密码**、删除 |
| 3 | 组件控制 | 外部组件状态与启停 | 启动/停止 AstrBot、NapCat、GPT-SoVITS，看登录二维码 |
| 4 | 媒体管理 | 本地媒体文件治理 | 预览、删除选中、按类型全部清理 |
| 5 | 系统日志 | 应用日志与审计日志 | 按级别/操作人筛选、刷新 |
| 6 | 配置管理 | 组件连接参数与 JWT | 编辑/保存/取消，带「需重启」徽标的改动要重启后端 |
| 7 | 数据维护 | 数据库备份与消息归档 | 立即备份、下载备份、执行归档 |
| 8 | 规则配置 | 计费与档位规则（含月卡与直购积分） | 改费率/折扣/档位价，**保存并立即生效** |
| 9 | 用户积分 | 用户积分总览 | **调整积分**（正数增加、负数扣减） |
| 10 | 积分流水 | 全站积分流水审计 | 多维筛选、导出 JSON |
| 11 | 订单管理 | 订单处理 | 确认收款、作废、退款、**+ 补单** |
| 12 | 退款审批 | 待审批退款（菜单带待办数） | 同意退款、驳回 |
| 13 | 纠纷处理 | 待处理纠纷（菜单带待办数） | 同意退款、驳回纠纷 |

> 提示：菜单里的「积分管理」是一个**分组标题**，不是页面；它下面从「规则配置」到「纠纷处理」共 6 项。后台没有子路由，刷新页面会回到「数据概览」。

## 页面要点

### 1—4：概览、用户、组件、媒体

| 页面 | 界面要点 | 关键操作与注意 |
|------|----------|----------------|
| 数据概览 | 7 张统计卡（总消息数、群聊总数、用户总数、AI 对话数、文件总数、AI 消息总数、上传文件占用）+ 消息趋势、活跃群聊/QQ 排行 TOP5、消息类型分布、时段分布、AI 对话趋势 | **纯只读**，除时间范围按钮外无写操作 |
| 用户管理 | 搜索用户名或昵称；列：ID、账号、昵称、角色、状态、最后登录、注册时间、操作 | **提权/降权**、**禁用/启用**、**重置密码**、**删除**（删除有二次确认且不可恢复）；20 条/页 |
| 组件控制 | 三张卡 AstrBot / NapCat / GPT-SoVITS，显示「运行中」或「已停止」 | **启动 / 停止**（进行中显示「启动中...」「停止中...」）、各自的 WebUI 链接、NapCat 区的**刷新二维码**与**下次自动登录**；状态每 5 秒刷新 |
| 媒体管理 | 汇总「共 N 个文件，占用 X」「已选 N 个，X」；筛选 **全部 / 图片 / 视频 / 音频**；列：文件名、类型、大小、创建时间 | **预览**、**预览全部**（相册模式支持全选/上一个/下一个）、**删除选中**、**全部清理**（按当前筛选类型，确认后不可恢复）；20 条/页 |

### 5—7：日志、配置、维护

| 页面 | 界面要点 | 关键操作与注意 |
|------|----------|----------------|
| 系统日志 | 两个子标签：**应用日志**（级别筛选 全部/INFO/WARN/ERROR/DEBUG，50 条/页）、**审计日志**（按操作人搜索 + 操作类型下拉，列 时间/操作人/操作类型/目标/结果/详情，20 条/页） | **刷新**；结果列绿色为成功、红色为失败 |
| 配置管理 | 5 组：AstrBot（API 地址、Token）、NapCat（API 地址、Token、Webhook Token）、GPT-SoVITS（API 地址、Token）、MinIO（Endpoint、Access Key、Secret Key）、JWT（Secret、过期时间） | **编辑 → 保存 / 取消**；密钥只回显掩码，编辑时「留空不修改」；带「需重启」徽标的项保存后要重启后端 |
| 数据维护 | **数据库备份**（立即备份、文件名/大小/时间、下载）、**消息归档**（「归档多少天前的消息」默认 90，范围 1~3650 + 执行归档） | 归档说明为「将指定天数之前的消息标记为已归档，归档后的消息不再在聊天界面中显示」；本页**只有备份、没有恢复按钮** |

### 8—13：积分与订单

| 页面 | 界面要点 | 关键操作与注意 |
|------|----------|----------------|
| 规则配置 | 左侧分节导航（基础奖励 / AI 对话计费 / 分析与语音 / 折扣与封顶 / 直购积分 / 会员月卡 / 费用试算）+ 右侧表单；顶部工具条：**已同步 / 有未保存的修改**、错误计数、重新加载、填入默认值、放弃修改、保存并立即生效 | 每个字段都有中文名、单位与说明；模型费率、分析类型倍率、阶梯折扣都是**可增删的行编辑器**（不再是 JSON 文本框）；折扣带「不打折 / 9 折 / 8 折 / 7 折 / 5 折」快捷按钮；**费用试算**用当前表单实时算出 AI 对话 / 群分析 / 语音各花多少积分，并折算成模拟现金 |
| 用户积分 | 搜索用户名或昵称；列：ID、用户名、昵称、角色、余额、订阅等级、订阅到期、累计收入、累计支出、消费封禁、操作 | 行内唯一按钮 **调整积分**（打开调账弹窗）；20 条/页 |
| 资金流水 | **时间范围**（今天 / 近 7 / 近 30 / 近 90 天 / 按筛选日期）→ 5 张 KPI 卡（现金收入、现金支出、净现金流、积分净变动、流水条数）→ 3 张图（现金收支趋势、现金构成、类型分布）→ 明细筛选（用户 ID、类型、方向、关联 ID、「只看有现金变动的」、日期、积分区间）→ 明细表（积分列 + **现金列** + 类别） | **手工记账**、**刷新**、**搜索**、**重置**、**导出 JSON**；20 条/页。原来只有积分口径，现已叠上**模拟现金账**（见下） |
| 订单管理 | 筛选：订单号、用户关键字、状态（待支付/已支付/退款审批中/纠纷中/已退款/已取消/已过期）、日期、金额区间 | **搜索**、**重置**、**导出 JSON**、**+ 补单**；行内 **详情 / 确认收款 / 作废 / 退款 / 处理纠纷 / 导出**；详情抽屉含订单快照、退款信息、时间轴、关联流水 |
| 退款审批 | 进入即只筛「退款审批中」；列：订单号、套餐、金额、用户 ID、退款原因、申请时间 | **同意退款**（全额，按比例扣回积分与月卡天数）、**驳回**（恢复「已支付」）；弹窗可填审批/驳回原因；**刷新** |
| 纠纷处理 | 进入即只筛「纠纷中」；列：订单号、套餐、金额、用户 ID、纠纷原因、申诉时间 | **同意退款**、**驳回纠纷**；弹窗「处理方式」二选一 + **处理说明必填**；**刷新** |

> 提示：处理纠纷后若提示「纠纷处理失败: action is not defined」而列表状态其实已变，这是提示文案的已知问题——刷新页面确认实际结果即可，不要重复提交。

### 积分规则怎么改才不出事

1. **改完看工具条**：出现「有未保存的修改」说明还没生效；点 **保存并立即生效** 才会写库（无需重启）。
2. **看右侧试算器再保存**：试算器用的是当前表单（含未保存修改），改「计费粒度 / 倍率 / 折扣」时可以直接看到一次对话从多少积分变成多少积分。
3. **改错了**：**放弃修改** 回到上次保存的状态；**填入默认值** 会用后端出厂默认值填充（同样要点保存才生效）；**重新加载** 丢弃本地改动并重新拉取。
4. **哪些字段容易踩**：
   - 计费粒度（tokenUnit）越大越便宜；输入/输出倍率决定提示词与回答的权重；
   - 月卡折扣只对月卡用户生效，直购积分档位不打折；
   - 阶梯折扣按**本月累计消耗**取最优一档，阈值必须是正整数；
   - 每日封顶填 0 = 不限；
   - 模型费率与分析类型倍率**建议保留 default 一行**，未列出的模型/类型按它计费。
5. **保存被拒**：页面会在对应字段下红字提示、导航上显示错误数；后端也会再校验一遍并返回 400（例如折扣写成 1.5、JSON 少了括号、阶梯阈值填了文字）。修好再保存即可，不会写坏规则。

> 现金相关：套餐价格同时决定后台「资金流水 → 模拟现金账」里的订阅收入；积分成本折算率（100 积分 = ¥1）来自后端配置 `credits.cash.cost-per-credit`，**不在这张表单里**。

### 资金流水里的「模拟现金账」怎么算

这一页同时给两个口径：**积分账**（原有的变动积分）与**现金账**（元）。现金是**模拟**的——
项目没有接真实支付通道，现金按规则折算，用来观察「钱从哪来、花到哪去」：

| 来源 | 现金怎么算 | 类别 |
|------|------------|------|
| 订阅购买 | 按套餐价（直购积分与月卡都读「规则配置」里的价格，默认 9.9 / 59 / 219 / 629 / 648 与月卡 30 / 68） | 订阅收入 |
| 订单退款 | **-(原单金额 × 退款比例)**，比例写在退款备注里；原单通过 `REFUND-SUB-xxx → SUB-xxx` 关联回查 | 订单退款 |
| AI 对话 / 分析 / 语音合成 | **-(消耗积分 × 折算率)**，默认 100 积分 = 1 元（`credits.cash.cost-per-credit`） | 模型调用成本 |
| 赠送 / 签到 / 月卡每日奖励 / 过期 | 与现金无关，记 0（明细里显示「—」） | — |
| **手工记账** | 管理员在弹窗里直接填金额（收入或支出），金额落库 | 手工记账 |

几个要点：

- **只读推算，不写库**：除手工记账外都不落库，历史数据无需回填；改了套餐价或折算率，图表口径自动跟着变。
- **手工记账不改积分**：写入的是一条 `CASH_INCOME` / `CASH_EXPENSE` 流水，积分变动为 0，可关联到某个用户（留空 = 全站级）。
- **趋势图**：柱=当日现金收入/支出，线=当日净现金流；没有流水的日期会补 0，折线不会断。
- **类型分布图**：按积分规模排序取前 6（否则 20 万积分的订阅会把其他类型压成看不见）。
- 时间范围内流水超过 2 万条时，页面会提示「统计只覆盖最近的部分数据」，缩小范围即可。


## 审计日志能追查什么

切到 **系统日志 → 审计日志**，用「按操作人搜索」定位管理员，或用操作类型下拉缩小范围：

| 操作类型 | 对应动作 |
|----------|----------|
| 角色变更 | 提权 / 降权 |
| 用户启停 | 禁用 / 启用 |
| 用户删除 | 删除用户 |
| 重置密码 | 用户管理里的重置密码 |
| 组件启动 / 组件停止 | 启动/停止 AstrBot、NapCat、GPT-SoVITS |
| 批量删除消息 | 按群批量删除消息 |
| 按类型删除消息 | 删除图片/视频/音频/文本/聊天记录 |
| 文件清理 / 文件删除 | 媒体管理里的全部清理 / 删除选中 |

## 常见管理动作

### 重置用户密码

1. 后台 → **用户管理**，搜索到目标账号。
2. 点 **重置密码**，在输入框里按提示填写新密码：**8-64 位，且同时包含大写字母、小写字母与数字**。
3. 规则不符会提示「密码不符合规则：需 8-64 位且含大小写字母与数字」；成功提示「用户 X 的密码已重置」。
4. **该用户的登录状态会立即失效**，需用新密码重新登录；本次操作写入审计日志。

> 提示：如果你自己是唯一管理员且忘了密码，需要另一个管理员账号操作，或按 [系统配置](system-config) 的部署方式处理。

### 给用户调账（发放或扣减积分）

1. 后台 → **用户积分**，搜索目标用户。
2. 点 **调整积分**，弹窗里「用户」「当前余额」为只读，需要填：

   | 字段 | 说明 |
   |------|------|
   | 调整金额 | **正数增加、负数扣减**，不能为 0 |
   | 调整原因 | **必填**，会写进审计日志 |

3. 点 **确认调整**，成功提示「已调整 X 积分 +N，新余额 M」；用户侧「用量明细」立刻出现一条「管理员调整」记录。识别失败之类的小额补偿走这里最方便。

### 补单（用户付款了但订单没到账）

1. 后台 → **订单管理** → **+ 补单**。
2. 填用户 ID、套餐，按需覆盖：自定义价格（单位是**分**）、自定义积分、时长（天）、自定义订单号、备注。
3. 提交后**直接创建「已支付」订单并发放积分**，提示「补单成功：<订单号> 已直接支付」。
4. 月卡的叠加与升级逻辑同样适用：给小月卡用户补大月卡会直接升为全功能版。

### 启动 / 停止组件

1. 后台 → **组件控制**，找到目标组件卡片。
2. 点 **启动** 或 **停止**，等待按钮从「启动中...」/「停止中...」恢复，状态文字随之更新。
3. NapCat 首次使用需点 **刷新二维码**，用手机 QQ 扫码登录机器人账号。
4. 操作会写入审计日志（组件启动 / 组件停止）。

> 提示：**RabbitMQ 与 MySQL 不在组件控制里**，需要在服务器上启动；后端启动失败时优先检查这两个。

### 排查故障的固定顺序

1. **数据概览**：消息是否还在进来、趋势是否异常。
2. **组件控制**：三个外部组件是否运行中、NapCat 是否已登录。
3. **系统日志（应用日志）**：按 ERROR / WARN 筛选看最近报错；AI 与媒体链路的排查关键词见 [AI 摘要](ai-summary) 与 [消息与媒体](messages)。
4. **订单管理 / 积分流水**：付费与扣费争议，用订单号或关联 ID 精确查。
5. **配置管理**：确认 Token、地址等参数有没有被改动过（改完注意「需重启」徽标）。

## 注意事项

| 事项 | 说明 |
|------|------|
| 高危操作 | 删除用户、删除群聊会话、清理媒体文件均**不可恢复**，操作前先做数据库备份 |
| 改配置需重启 | 带「需重启」徽标的配置项保存后需重启后端才生效 |
| 规则改动立即生效 | 「规则配置」保存后立刻影响后续计费，改费率前最好先通知用户 |
| 组件状态只是端口检测 | 「运行中」不代表 QQ 已登录、也不代表模型可用 |
| 后台无子路由 | 刷新会回到数据概览，协作时请用菜单名说明位置 |
| 权限边界 | 管理员账号能改费率、调账与删数据，请勿外借，离开时记得退出登录 |

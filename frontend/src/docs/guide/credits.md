积分是这套系统里的「通用货币」：**AI 对话、AI 分析、语音合成、群类型识别都要花积分**，签到、月卡与购买是主要来源。这一页把规则、默认数值和查看入口讲清楚。

## 积分从哪来

| 来源 | 默认数值 | 发放时机 | 备注 |
|------|----------|----------|------|
| 新人注册赠送 | **500** | 首次为账号建立积分账户时 | 只发一次，不重复发 |
| 每日签到（基础分） | **150** | 每天签到一次 | 断签后连续天数从 1 重新计 |
| 小月卡每日额外 | **+100** | 随每日签到一起发放 | 需要月卡在有效期内 |
| 大月卡每日额外 | **+300** | 随每日签到一起发放 | 需要月卡在有效期内 |
| 小月卡 + 大月卡双持 | **+400** | 随每日签到一起发放 | 两张卡叠加（100 + 300） |
| 购买积分档位 | 2000 / 4000 / 12000 / 40000 / 100000 | 管理员确认收款后到账 | 见 [订阅与订单](subscription) |
| 购买月卡 | 小月卡 3000 / 大月卡 8000 | 管理员确认收款后到账 | 与每日额外积分是两笔 |
| 管理员补单 / 调账 | 由管理员指定 | 管理员操作后立即到账 | 明细里显示为管理员发放 |

所有数值都可以由管理员在后台「规则配置」里调整，**以你界面上看到的数字为准**。

> 提示：积分**不会过期**。系统里没有积分失效机制，攒着不会清零（退款时会被按比例扣回，见下）。

## 每日签到

### 怎么签

1. 进入 **用户中心 → 用量管理**（侧边栏顶部的积分徽章也能进）。
2. 顶部横幅显示今日可得的签到积分，例如「欢迎使用积分体系 · 每日签到 +150」。
3. 点击 **立即签到**（提交中显示「签到中...」）。
4. 成功后按钮变为 **今日已签**（不可再点），弹提示「签到成功 +150」；持有月卡时会显示「签到成功 +250（含月卡额外 +100）」这类文案。

### 规则

| 项目 | 说明 |
|------|------|
| 频率 | **每天一次**，按自然日计算（服务器时区 Asia/Shanghai） |
| 重复签到 | 提示「今天已签到过了」 |
| 连续天数 | 横幅显示「已连续签到 N 天」；昨天签过则 +1，否则从 1 开始 |
| 月卡加成 | 与基础分**同一次到账**，不需要额外操作 |
| 加成口径 | 小月卡 +100、大月卡 +300、双持（全功能版）+400 |
| 今日已发过加成 | 界面会显示「含月卡额外 +N（今日已发放）」 |
| 签到日历 | 接口提供近 7 天或本月的签到记录，界面目前只展示「连续签到天数」 |

> 提示：月卡每日额外积分**只在签到时发放**，不再随登录自动到账。所以买了月卡也别忘了每天点一次签到——不签就拿不到那 +100 / +300 / +400。

### 月卡加成的展示位置

- 横幅里的金色标签：`含小月卡额外 +100`、`含大月卡额外 +300`、双持时显示 `含大小月卡额外 +400`。
- 侧边栏头像菜单：显示当前积分与 **今日已签 / 立即签到** 按钮。
- 积分不足时的提示条也会带 **去签到** 按钮。

## 积分怎么消耗

| 用途 | 计费方式 | 默认口径 |
|------|----------|----------|
| AI 对话 | 按 Token 用量 | 每 1000 Token 折算，输入单价比输出便宜；单次有最低消费 |
| AI 对话（带图） | 每张图片额外计费 | 每张 **+5** 积分 |
| AI 对话（长上下文） | 超出免费条数的历史消息每条额外计费 | 前 **10** 条免费，之后每条 **+1** |
| AI 分析（选中消息） | 基础费 + 按消息条数 | 基础 **10** + 每条 **1** |
| TTS 语音合成 | 按字符数 | 每 **50** 字符 1 积分，单次最低 **2** 积分 |
| 群类型 AI 识别 | 固定 | **1** 积分/次（识别失败不扣） |

默认的 AI 对话费率参数（管理员可改）：

| 参数 | 默认值 | 含义 |
|------|--------|------|
| 每多少 Token 计费 | 1000 | 计费单位 |
| 输入倍率 | 2 | 每单位输入 Token 的积分 |
| 输出倍率 | 4 | 每单位输出 Token 的积分 |
| 单次最小消耗 | 5 | 再短的对话也不会低于这个数 |
| 默认每条消耗 | 10 | 拿不到 Token 用量时按此计费 |
| 模型费率倍数 | `{"default":1.0}` | 贵模型可单独设更高倍数 |
| 超配额倍率 | 1.5 | 月度免费额度用完后加倍 |
| 月度免费配额 | 0（不启用） | 设为 N 时，当月前 N 次对话免费 |
| 每日封顶 | 0（不启用） | 设为 N 时，当天累计消费达到 N 后，当天后续调用免费 |

### 折扣怎么叠加

实际扣费 = 基础费用 × 模型倍数 × 超配额倍率 × **月卡折扣** × **阶梯累计折扣**，逐项相乘：

| 折扣类型 | 默认 | 生效条件 |
|----------|------|----------|
| 小月卡专属折扣 | **9 折** | 持有有效小月卡 |
| 大月卡专属折扣 | **8 折** | 持有有效大月卡 |
| 全功能版折扣 | **7 折** | 同时持有小月卡与大月卡 |
| 阶梯累计折扣 | 本月累计消费 ≥1000 打 **95 折**；≥5000 打 **9 折**；≥20000 打 **85 折** | 按**本月**累计消费自动生效 |

> 提示：阶梯折扣按自然月累计，月初会重置。月卡折扣与阶梯折扣可以叠加，所以长期高频使用的账号，越到月底单价越低。

### 免费与豁免

| 场景 | 是否扣积分 |
|------|------------|
| 管理员账号（默认开启「管理员免费」） | 不扣，明细里记录为 `ADMIN_FREE` |
| 识别群类型但识别失败 | 不扣 |
| AI 对话 / 分析 / TTS 调用失败 | 可退费（明细里出现「退款」类型的收入） |
| 月度免费配额内的 AI 对话 | 不扣（管理员启用该配额时） |
| 当日已达每日封顶额度 | 不扣（管理员启用封顶时） |
| 账户被标记为「禁止消费」 | 直接拒绝，无法调用 |

积分不足时界面会明确提示，例如「积分不足（需 N 积分，当前 M），请升级权益或完成签到」，并给出 **去签到** 与 **升级权益** 两个按钮。

## 签到 / 用量管理页面怎么看

进入 **用户中心 → 用量管理**，从上到下是四块内容：

### 1. 签到卡（顶部横幅）

显示今日签到可得积分、月卡额外加成、连续签到天数与签到按钮。

### 2. 总可用积分卡

| 展示项 | 含义 |
|--------|------|
| 总可用积分 | 当前余额，所有消费都从这个数里扣 |
| 累计收入 | 历史上所有入账之和（含退款） |
| 累计支出 | 历史上所有出账之和（退款不回退此数，便于看真实消费量） |
| 当前订阅 | 当前权益档位与到期日；无月卡时显示免费版 |
| 升级权益 | 跳转到订阅管理页 |

### 3. 用量明细

- 头部三项：**收入合计 / 支出合计 / 净额**（当前筛选范围内）。
- 标签切换：**全部 / 收入 / 支出**。
- 筛选条件：类型下拉、开始日期、结束日期、订单号/对话号，右侧 **查询** 与 **重置**。
- 表格列：**时间、类型、变动积分、余额、备注、relatedId**。
- 正负号：收入显示绿色 `+N`，支出显示红色 `-N`；「余额」是该笔之后的余额。
- `relatedId` 是关联编号（订单号或对话号），点击可复制，商户对账/找管理员排查时用得上。
- 每页 20 条，底部分页；没有记录时提示「暂无明细，去 AI 对话或签到吧」。

明细里的类型中文含义：

| 类型 | 含义 |
|------|------|
| AI 对话 | AI 聊天扣费 |
| 每日签到 | 签到到账（含月卡加成时以备注区分） |
| 订阅购买 / 订阅续费 | 购买套餐或月卡到账 |
| 新用户福利 | 新人注册赠送 |
| 退款 | 调用失败或订单退款回补 |
| 管理员调整 | 管理员调账（发放或扣减） |
| 月卡每日奖励 | 月卡每日额外积分（随签到发放时可见） |
| 其他 | 未归类的流水 |

### 4. 积分趋势

- 时间范围按钮：**7天 / 30天**（默认 7 天）。
- 三条数据：**收入**（绿线）、**支出**（红线）、**净额**（柱状，正数绿、负数红）。
- 用来看「哪天花了多少」，排查异常扣费最直观。

## 常见问题

| 现象 | 原因与处理 |
|------|------------|
| 签到按钮是「今日已签」 | 今天已经签过，明天再来；按钮不可点属正常 |
| 买了月卡但签到没多给 | 需要在**月卡有效期内**且当天尚未签到；确认订单状态是「已支付」 |
| 提示「积分不足」 | 先签到，或到订阅管理购买积分档位；也可以减少上下文长度与图片数量 |
| 同一句话两次扣费不一样 | 输出长度、历史上下文条数、图片数量都会影响费用，属正常 |
| 余额比预期少很多 | 在「用量明细」按日期筛选，看是否有大额 AI 对话或 TTS 消费 |
| 明细里出现负数余额之外的异常 | 把该行 `relatedId` 复制给管理员，可据此定位到具体订单/对话 |
| 管理员操作后积分没变 | 让管理员确认调账是否成功（明细会立刻出现「管理员调整」记录） |
